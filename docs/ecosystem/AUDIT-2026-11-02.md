## Fitsin audit and financial constraints

- Existing code includes dated manual entries, day line breakdowns, seller payout flags and push deep links from `bc2fd55`. These are assessed as existing capabilities, not proposed replacements.
- Today awaited Today and Month before assigning either. Month awaited a separate goal endpoint before assigning the month response which already contains its goal. Foreground eagerly refreshed hidden tabs; timers and view tasks could overlap. These are verified source paths, not proof of the owner's live symptom.
- Backend cache misses ran one producer per caller. Today and Month independently fetch history and seller deductions. Coalescing identical endpoint work now avoids a measured burst, but does not yet share history across distinct endpoints or processes.
- The upstream helper previously allowed three 15-second attempts plus backoff, discarded a caller's abort signal, and stopped the timer at response headers. A stalled body or repeated pages could exceed the iOS 20-second timeout. New cached-response work has a shared 18-second upstream budget and aborts bodies/backoff; each individual fetch also has a 15-second budget. This is not a guarantee for host cold start, CPU stalls or filesystem hangs, and uncached detail endpoints still need end-to-end profiling.
- Cache invalidation could be undone by a producer started before a mutation. Flights are now detached on invalidation; old completions cannot fill a new cache generation. Current-day/month keys use London periods; existing response fields and TTL/stale limits are retained.
- Manual sale failure previously cleared the input and used a green notice. It now keeps the fields, returns an explicit failure, prevents simultaneous submissions in the view model and warns the user to check recent entries before retrying an uncertain response. It does **not** claim durable idempotency for manual writes.
- Local cache remains synchronous and shared under the existing app access model. Atomic writes and period checks are added; full identity-scoped/versioned/bounded asynchronous storage is a follow-up, not falsely claimed complete. No new seller data is exposed.
- The app has an embedded shared API credential, while the user name/PIN is local. Neither is a named server-side seller permission. Warm-up now uses the same request builder and the cheap health route. Credential replacement/rotation needs a compatibility and identity plan; no value is reproduced here.
- Calendar's active iOS authority is Google Calendar (`CalendarService` / Google sign-in), not the backend's retained Notion routes. Rota is Fitsin JSON-backed state. README endpoint/auth descriptions are historical; the project spec points at Render, but live routing and hosting cold starts are unverified.

Financial issues deliberately not concealed by performance changes:

1. Fitsin uses fixed name-prefix mappings and 15% commission. Deductions use original line prices; discounts/refunds/current order totals can differ. Neither these line amounts nor Crosstopher asking prices constitute an approved settled-proceeds ledger.
2. `metrics.js` catches deduction failures and substitutes an empty map; that can overstate store revenue without an incompleteness flag. The new deadline check prevents an expired shared deadline becoming a successful cache fill, but other deduction errors retain existing behaviour. Resolve semantics before trustworthy reporting.
3. Manual source `cash` is not proof a sale is absent from Shopify POS. Existing manual records have stable IDs but no source order/garment relationship; repeated POSTs can duplicate a sale.
4. JSON files use atomic rename, but read-modify-write operations are not serialised across concurrent writers/processes. Manual aggregation requests 5,000 entries but `listManualEntries` clamps to 1,000. These need separate synthetic correctness fixes before relying on larger financial datasets.
5. Fitsin webhook verification is conditional on configured secret/header, lacks persistent delivery deduplication, and catches errors with HTTP 200. These are source findings, not a live security test; do not add cross-seller notifications or new financial consumers on this boundary.
6. Payout flags indicate a team-marked line payment, not bank settlement or refund reconciliation.
